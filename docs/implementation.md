# FuckTheRocks — 第一版实现方案

## 1. 工程状态与原则

旧版网站实现已经退出方案，不进行增量改造。新版本从新的路由、布局、样式和内容集合开始建立；原始资料、内容母稿、来源底账和资料处理脚本继续保留。

实现遵循以下原则：

- 使用 Astro 6、TypeScript 与 Tailwind CSS 4；
- 默认生成静态 HTML；
- Three.js 只负责首页三维场景，不接管页面文字与路由；
- GSAP 负责首页高层滚动编排和缓动，原生滚动始终保留；
- 探索页优先使用 HTML 与 SVG，不复制首页的 WebGL 方案；
- 内容在构建时读取，正文不依赖浏览器二次请求；
- 客户端交互按页面局部加载，不把整站改成单页应用；
- 基础 HTML 始终可用，高级效果只做增强。

## 2. 路由与计划目录

第一版只有三个路由：

~~~text
src/pages/
├─ index.astro
├─ explore.astro
└─ 404.astro
~~~

建议的实现结构：

~~~text
src/
├─ components/
│  ├─ home/
│  │  ├─ AlbumSphere.astro
│  │  └─ album-sphere.ts
│  ├─ explore/
│  │  ├─ Timeline.astro
│  │  ├─ RelationGraph.astro
│  │  ├─ NodeDetail.astro
│  │  └─ explore-state.ts
│  └─ shared/

~~~

## 3. 首页实现

### 3.1 渲染边界

首页同时包含两层：

- **HTML 层**：品牌、定位、当前年份、当前专辑信息、滚动提示和探索入口；
- **WebGL 层**：专辑封面平面、球面构图、光照、旋转和相机变化。

HTML 必须先于三维初始化可见。Canvas 设置为非语义视觉层，不能遮挡链接和按钮。

### 3.2 Three.js 场景

第一版场景包含：

- 一个 PerspectiveCamera；
- 一个 WebGLRenderer；
- 一个承载全部封面的 Group；
- 一份共享 PlaneGeometry；
- 24—40 个使用不同封面纹理的 Mesh；
- 必要的环境光、方向光或自定义材质；
- 用于聚焦计算的时间顺序和球面坐标数据。

专辑按照编辑后的时间顺序排列在球面螺旋上。每张专辑至少具有：

~~~ts
type HomeAlbum = {
  id: string;
  title: string;
  artist: string;
  year: number;
  genres: string[];
  cover: string;
  coverAlt: string;
  homeOrder: number;
};
~~~

初版只有几十张不同纹理，不强制使用 `InstancedMesh`。共享几何体、复用材质设置、纹理尺寸控制和视锥剔除已经足够；只有封面规模明显扩大后，才评估纹理图集、纹理数组或自定义 Shader 的实例化方案。

### 3.3 滚动编排

- 使用页面原生滚动位置计算 0—1 的进度；
- GSAP 或渲染循环中的阻尼插值将进度映射到场景组旋转；
- 相机只做小幅 dolly、偏移和构图调整；
- 不对 `wheel` 调用 `preventDefault()`；
- 滚动进度同时驱动当前年代和当前专辑的 HTML 状态；
- 只有状态真正变化时才更新 DOM，避免每帧重写文字；
- 页面不可见时暂停渲染，重新可见时恢复；
- 监听 WebGL context lost，发生时切换到静态视觉。

### 3.4 指针与选择

- 指针位置只产生小幅视差；
- 当前专辑由滚动位置主导，避免鼠标悬停与滚动争夺状态；
- 点击当前专辑或 HTML 中的对应入口，进入 `/explore?album=<id>` 或相关年代状态；
- 键盘用户通过可聚焦的 HTML 控件完成同等操作，不要求直接操作 Canvas。

### 3.5 纹理与性能

- 封面使用经过授权或可合法展示的本地优化版本；
- 为每张封面记录来源、替代文本和必要的权利说明；
- 根据显示尺寸输出 AVIF/WebP 或其他合适格式，不直接上传超大原图；
- 首批只加载建立首屏所需的纹理，其余在浏览器空闲或接近使用时加载；
- 限制渲染器 pixel ratio，桌面通常不超过 2，简化模式进一步降低；
- 移动端减少封面数量、材质复杂度和非必要光照；
- 不在首页加载探索页关系图代码。

首批纹理体积、帧率和内存预算以真实原型在桌面与移动设备上实测确定，不通过设备名称硬编码能力。

## 4. 三种能力模式

### 完整模式

适用于支持 WebGL、未请求减少动态效果且原型运行稳定的环境：

- 完整专辑数量；
- 滚动旋转与阻尼；
- 小幅相机变化；
- 小幅指针视差；
- 探索页完整的关系过渡。

### 简化模式

适用于触控设备、较小屏幕或运行表现不足的环境：

- 减少可见专辑和纹理分辨率；
- 降低 pixel ratio；
- 关闭指针视差和非必要材质效果；
- 保留滚动、年份变化和探索入口；
- 探索页减少同时显示的边和过渡。

### 静态模式

适用于 `prefers-reduced-motion: reduce`、WebGL 初始化失败、context lost 或脚本不可用的环境：

- 首页显示预先排版的静态封面视觉；
- 品牌文案、当前定位和探索入口完整保留；
- 探索页使用按年代组织的 HTML 与文字关系索引；
- 错误页本来就只使用静态模式。

模式切换必须是增强逻辑，不能先隐藏基础内容再等待 JavaScript 决定是否显示。

## 5. 探索页实现

### 5.1 服务端输出

Astro 在构建时读取年代、历史事件、流派关系和代表专辑，生成统一视图数据。服务端直接输出：

- 按年代组织的完整 HTML；
- 核心流派节点；
- 历史事件摘要；
- 代表专辑信息；
- 文字关系索引；
- 页面内节点详情；
- 搜索所需的轻量索引。

禁用 JavaScript 时，用户仍能顺序阅读时间线并使用锚点访问详情。

### 5.2 布局策略

探索页不使用自由漂移的力导向图作为默认布局。节点坐标由内容的时间位置和编辑确定的分支泳道共同决定：

- 纵轴由形成时间或主要活跃阶段计算；
- 横轴由根源、Punk/Post-Punk/Alternative、Metal 等编辑分支提供初始泳道；
- 融合关系可以跨泳道；
- 客户端只做局部避让、聚焦和视口适配，不在每次加载时重新随机布局。

这种方式保证相同内容每次打开都出现在可预测位置，并让时间结构优先于图形算法。

### 5.3 SVG 与 HTML 分工

- HTML 节点承载可读文字、按钮和语义；
- SVG 绘制关系线、箭头、范围和图例；
- 关系线默认不接收焦点；
- 选择 HTML 节点后更新 SVG 高亮；
- 图谱增强失败时隐藏 SVG，不隐藏 HTML 时间线；
- 关系类型通过线型、箭头、标签和颜色共同表达。

### 5.4 页面状态

客户端负责：

- 当前年代和阅读进度；
- 搜索与筛选；
- 节点选择和一跳关系聚焦；
- 详情面板的打开、关闭与焦点管理；
- URL 查询参数同步；
- 浏览器前进后退恢复；
- 关闭详情后的滚动位置和触发焦点恢复。

建议查询参数：

~~~text
/explore?genre=post-punk
/explore?era=1980s
/explore?album=unknown-pleasures
~~~

状态更新使用 History API，不建立客户端路由。

## 6. 基础错误页

`404.astro` 只包含：

- 正确的页面标题与错误说明；
- 返回首页链接；
- 进入探索链接；
- 与全站一致的基础字体、色彩和布局。

错误页不加载 Three.js、GSAP、搜索索引或探索图代码。

## 7. 内容模型

第一版保留三个内容集合，让流派、年代事件和专辑可以独立维护并互相引用。

### Genre

~~~yaml
name_zh: 中文名
name_en: Original Name
aliases: []
summary: 简要定义
emergence: late-1970s
codified: early-1980s
places: []
derived_from: []
fusion_sources: []
influenced_by: []
related_scenes: []
sources: []
body: Markdown 正文
~~~

后继流派由 `derived_from` 等正向关系反向计算，避免同时维护两份关系。直接衍生、融合、影响和场景承接不能混入一个通用 `parents` 字段。

### Era

~~~yaml
label: 1970s
title: 年代标题
order: 1970
summary: 年代概述
events:
  - id: stable-event-id
    date: 1977
    title: 节点标题
    summary: 节点摘要
    genres: []
    albums: []
    sources: []
~~~

### Album

~~~yaml
title: Album Title
artist: Artist Name
year: 1979
genres: []
cover: 可选本地资源
cover_alt: 封面替代文本
cover_source: 来源
rights_note: 必要时记录展示依据
featured_on_home: true
home_order: 12
sources: []
~~~

代表专辑不生成独立页面。首页和探索页读取同一份 Album 数据。

## 8. 内容与关系规则

- 所有实体使用稳定、可读的 ID；
- 引用只保存 ID，不复制名称；
- 构建时检查不存在的引用；
- 流派关系允许多个直接来源、融合来源和影响来源；
- 构建时检测直接衍生关系的循环；
- 删除内容前检查反向引用；
- 每条核心关系保留来源或编辑依据；
- 不确定关系可以进入资料母稿，但不直接进入默认图谱；
- 封面、照片和外部文字均保留来源及必要权利信息。

内容集合使用 Astro Content Collections 的 glob loader。Schema 只描述已由真实样本验证的稳定字段，不为尚未确认的数据提前建模。

## 9. 客户端代码边界

客户端代码只用于：

- 首页 Three.js 场景与滚动编排；
- 探索页阅读进度、搜索筛选和节点详情；
- SVG 关系线的局部聚焦与响应式适配；
- URL 和浏览器历史状态同步。

以下内容不依赖客户端请求：

- 页面主要标题与说明；
- 年代和历史正文；
- 核心流派信息；
- 代表专辑文字资料；
- 错误页恢复入口。

## 10. 验证要求

每个阶段至少验证：

- Astro 类型检查无错误；
- 静态生产构建成功；
- 只有三个第一版页面路由；
- 所有内部引用有效；
- 封面资源和来源字段完整；
- 桌面与移动布局；
- 键盘浏览和焦点恢复；
- `prefers-reduced-motion`；
- 首页完整、简化和静态模式；
- WebGL 初始化与 context lost 降级；
- 首页入口在脚本加载前后均可使用；
- 探索网络失败时的文字降级；
- 节点深链接、前进后退和关闭后的状态恢复；
- 404 页面不加载重型客户端代码；
- 页面标题、描述、规范链接和分享信息。

首页还需在真实中端移动设备上检查帧率、发热、纹理内存和长时间滚动；探索页需检查 SVG 边数量、正文可读性和触控操作。

## 11. 发布

构建产物为静态文件，部署到支持自定义域名的平台并绑定 `fuckthe.rocks`。发布平台在整合阶段根据缓存、自定义错误页、资源压缩和域名配置实测确定。
