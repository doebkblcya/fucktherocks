# FuckTheRocks — 第一版实现方案

## 1. 工程状态与原则

旧版网站实现已经退出方案，不进行增量改造。新版本从新的路由、布局、样式和内容集合开始建立；原始资料、内容母稿、来源底账和资料处理脚本继续保留。

实现遵循以下原则：

- 使用 Astro 6、TypeScript 与 Tailwind CSS 4；
- 默认生成静态 HTML；
- Three.js 只负责首页三维场景，不接管页面文字与路由；
- GSAP 负责首页高层滚动编排和缓动，原生滚动始终保留；
- 探索页使用文字优先的 HTML 时间链、索引和原生行内详情，不复制首页的 WebGL 方案；
- 内容在构建时读取，正文不依赖浏览器二次请求；
- 客户端交互按页面局部加载，不把整站改成单页应用；
- 基础 HTML 始终可用，高级效果只做增强。

## 3. 首页实现

### 3.1 渲染边界

首页同时包含两层：

- **HTML 层**：品牌、当前年份与专辑的一句话信息签、探索入口；
- **WebGL 层**：从球体内部观看的真实专辑封面、球面空间线与连续镜头环视。

HTML 必须先于三维初始化可见。Canvas 设置为非语义视觉层，不能遮挡链接和按钮。

### 3.2 Three.js 场景

第一版场景包含：

- 一个位于球心附近、朝向封面的 PerspectiveCamera；
- 一个 WebGLRenderer；
- 共享的封面、纸边和阴影平面几何体；
- 首轮 30 组使用不同封面纹理的展品，每组只有少量 Mesh；
- 简单的无光照材质，让封面本身保持辨识度；
- 用于聚焦计算的时间顺序和球面坐标数据。

专辑按照编辑后的时间顺序排列在朝向球心的球面螺旋上。每张专辑至少具有：

~~~ts
type HomeAlbum = {
  id: string;
  title: string;
  artist: string;
  year: number;
  branch: string;
  intro: string;
  musicbrainzId?: string;
  coverRelease?: string;
};
~~~

初版只有几十张不同纹理，不强制使用 `InstancedMesh`。共享几何体、复用材质设置、纹理尺寸控制和视锥剔除已经足够；只有封面规模明显扩大后，才评估纹理图集、纹理数组或自定义 Shader 的实例化方案。

### 3.3 滚动编排

- 使用页面原生滚动位置计算 0—1 的进度；
- GSAP 或渲染循环中的阻尼插值将进度映射到镜头的观看方向；
- 相机留在球体内部，只保留小幅位置偏移，不翻滚或高速推进；
- 不对 `wheel` 调用 `preventDefault()`；
- 滚动进度同时驱动当前年代和当前专辑的 HTML 状态；
- 焦点封面沿球面法线稍向内移动、轻微放大；同一焦点值驱动纸边、阴影和信息签切换；
- 只有状态真正变化时才更新 DOM，避免每帧重写文字；
- 页面或标签不可见时暂停渲染，重新可见时恢复；
- 监听 WebGL context lost，发生时切换到静态视觉。

### 3.4 输入与导航

- 当前专辑仅由原生滚动位置决定；
- 桌面指针只产生几度以内的轻微倾斜，不改变滚动所决定的当前专辑；封面暂不作为可点击控件；
- 顶部 HTML 导航始终可用，键盘用户无需操作 Canvas。

### 3.5 纹理与性能

- 封面由 MusicBrainz 与 Cover Art Archive 的公开接口抓取为本地原型素材；来源与权利状态记录于 `public/covers/manifest.json`；
- 当前封面权利尚未核实，仅用于本地设计评审；公开部署前须确认展示权利或替换素材；
- 首轮为每张封面使用约 500px 的缩略图，后续按实测优化格式和加载策略；
- 首屏优先加载视线附近的封面，滚动时预取即将进入视野的纹理；
- 限制渲染器 pixel ratio，桌面通常不超过 2，简化模式进一步降低；
- 移动端降低渲染分辨率，维持同一份少量封面；
- 不在首页加载探索页索引代码。

首批纹理体积、帧率和内存预算以真实原型在桌面与移动设备上实测确定，不通过设备名称硬编码能力。

## 4. 三种能力模式

### 完整模式

适用于支持 WebGL、未请求减少动态效果且原型运行稳定的环境：

- 完整专辑数量；
- 滚动环视与阻尼；
- 球心附近的小幅镜头位移；
- 桌面端轻微指针倾斜；
- 探索页完整的关系过渡。

### 简化模式

适用于触控设备、较小屏幕或运行表现不足的环境：

- 减少同时可见的封面并限制渲染分辨率；
- 降低 pixel ratio；
- 关闭指针倾斜并维持简单材质；
- 保留滚动、年份变化和探索入口；
- 探索页减少同时显示的边和过渡。

### 静态模式

适用于 `prefers-reduced-motion: reduce`、WebGL 初始化失败、context lost 或脚本不可用的环境：

- 首页显示预先排版的静态封面视觉；
- 品牌字样、当前专辑信息和探索入口完整保留；
- 探索页使用按年代组织的 HTML 与文字关系索引；
- 错误页本来就只使用静态模式。

模式切换必须是增强逻辑，不能先隐藏基础内容再等待 JavaScript 决定是否显示。

## 5. 探索页实现

### 5.1 服务端输出

Astro 在构建时读取 11 段时间数据、95 个条目和证据较充分的文字关系。内容由 `docs/materials/explorable-rock-map.md` 的第一轮编辑稿转换到 `src/data/explore-*.json`，不在运行时解析 Markdown。服务端直接输出：

- 按年代组织的完整时间链 HTML；
- 四条脉络下的全部流派／场景名称、类型与形成区间；
- 原生 `details` 定义与文字关系；
- 搜索所需的轻量文本索引。

禁用 JavaScript 时，用户仍能顺序阅读时间线并使用锚点访问详情。

### 5.2 布局与关系

时间段和分类索引均由 HTML 按固定编辑顺序呈现；默认不绘制 SVG 连线或力导向图。关系数据只在条目展开时以有名称的文字链接显示。分类组是导航归档，不构造唯一父子树；资料底账中证据等级 C 的假设关系暂不入站。

### 5.3 页面状态

客户端只负责搜索筛选、时间链跳转到条目、条目展开和 `/explore?genre=post-punk` 查询参数同步。不建立客户端路由。JavaScript 不可用时原生锚点和 `details` 保留基本阅读能力。

## 6. 基础错误页

`404.astro` 只包含：

- 正确的页面标题与错误说明；
- 返回首页链接；
- 进入探索链接；
- 与全站一致的基础字体、色彩和布局。

错误页不加载 Three.js、GSAP、搜索索引或探索图代码。

## 7. 内容模型

第一版保留三个内容集合，让流派、年代事件和专辑可以独立维护并互相引用。

### Genre

~~~yaml
name_zh: 中文名
name_en: Original Name
aliases: []
summary: 简要定义
emergence: late-1970s
codified: early-1980s
places: []
derived_from: []
fusion_sources: []
influenced_by: []
related_scenes: []
sources: []
body: Markdown 正文
~~~

后继流派由 `derived_from` 等正向关系反向计算，避免同时维护两份关系。直接衍生、融合、影响和场景承接不能混入一个通用 `parents` 字段。

### Era

~~~yaml
label: 1970s
title: 年代标题
order: 1970
summary: 年代概述
events:
  - id: stable-event-id
    date: 1977
    title: 节点标题
    summary: 节点摘要
    genres: []
    albums: []
    sources: []
~~~

### Album

~~~yaml
title: Album Title
artist: Artist Name
year: 1979
genres: []
cover: 可选本地资源
cover_alt: 封面替代文本
cover_source: 来源
rights_note: 必要时记录展示依据
featured_on_home: true
home_order: 12
sources: []
~~~

代表专辑不生成独立页面。首页和探索页读取同一份 Album 数据。

## 8. 内容与关系规则

- 所有实体使用稳定、可读的 ID；
- 引用只保存 ID，不复制名称；
- 构建时检查不存在的引用；
- 流派关系允许多个直接来源、融合来源和影响来源；
- 构建时检测直接衍生关系的循环；
- 删除内容前检查反向引用；
- 每条核心关系保留来源或编辑依据；
- 不确定关系可以进入资料母稿，但不直接进入探索页；
- 封面、照片和外部文字均保留来源及必要权利信息。

当前探索页使用构建期导入的 JSON 数据；逐条核对和来源字段稳定后，再考虑迁移到 Astro Content Collections，不为尚未确认的数据提前建模。

## 9. 客户端代码边界

客户端代码只用于：

- 首页 Three.js 场景与滚动编排；
- 探索页搜索、条目跳转与展开；
- 流派查询参数和浏览器历史状态同步。

以下内容不依赖客户端请求：

- 页面主要标题与说明；
- 年代和历史正文；
- 核心流派信息；
- 代表专辑文字资料；
- 错误页恢复入口。

## 10. 验证要求

每个阶段至少验证：

- Astro 类型检查无错误；
- 静态生产构建成功；
- 只有三个第一版页面路由；
- 所有内部引用有效；
- 封面资源和来源字段完整；
- 桌面与移动布局；
- 键盘浏览和焦点恢复；
- `prefers-reduced-motion`；
- 首页完整、简化和静态模式；
- WebGL 初始化与 context lost 降级；
- 首页入口在脚本加载前后均可使用；
- 无 JavaScript 时的时间链、索引和原生详情；
- 流派深链接和前进后退；
- 404 页面不加载重型客户端代码；
- 页面标题、描述、规范链接和分享信息。

首页还需在真实中端移动设备上检查帧率、发热、纹理内存和长时间滚动；探索页需检查长列表阅读、搜索、键盘与触控操作。

## 11. 发布

构建产物为静态文件，部署到支持自定义域名的平台并绑定 `fuckthe.rocks`。发布平台在整合阶段根据缓存、自定义错误页、资源压缩和域名配置实测确定。
