# FuckTheRocks — 第一版实现方案

## 1. 技术原则

- 使用 Astro 6、TypeScript 与 Tailwind CSS 4；
- 默认生成静态 HTML；
- 内容优先由服务端构建，交互按页面局部加载；
- 首页允许较重的视觉代码，探索页按需加载关系图交互；
- 基础 HTML 始终可用，高级效果只做增强。

## 2. 路由

~~~text
src/pages/
├─ index.astro
└─ explore.astro
~~~

全站布局只提供首页和探索两个主要导航项。历史事件与流派详情在探索页内展开；第一版不生成 `/history`、`/taxonomy` 或 `/genres/[slug]`。

## 3. 页面组成

### 首页

- 静态 HTML 提供品牌文案和一个探索入口；
- 客户端视觉场景负责黑胶、时间轨迹和流派网络过渡；
- 根据运行能力选择 WebGL/Canvas、SVG/CSS 或静态模式；
- 声音模块在用户主动开启后加载。

视觉实现先做独立原型，再决定具体渲染库，避免在效果验证前绑定技术。

### 探索页

- 构建时读取年代、历史事件、流派关系和代表专辑，并生成统一图数据；
- 服务端输出按年代组织的完整 HTML 和文字索引；
- 客户端组件负责关系线布局、年代定位、筛选、聚焦和节点选择；
- 默认状态以纵向时间阅读为主，选中流派后只高亮局部关系网络；
- 节点详情在侧栏、浮层或行内区域渲染，不请求新的内容页面；
- 使用 URL 查询参数或锚点保存选中节点，支持深链接和浏览器前进后退；
- 禁用 JavaScript 或关系图加载失败时，仍可顺序阅读全部历史并通过文字链接查看节点信息。

### 页面内节点详情

- 构建时解析流派的来源、衍生、融合、影响、历史事件和代表专辑引用；
- 所有主要节点详情预先存在于页面 HTML 或构建产物中，选择节点时不依赖远程接口；
- 客户端只控制显示状态、焦点管理和 URL 同步；
- 关闭详情后恢复之前的视口、筛选和键盘焦点。

## 4. 内容模型

页面合并不等于数据混成一张表。第一版保留三个内容集合，让历史事件、流派和专辑仍可独立维护并互相引用。

### Genre

~~~yaml
name_zh: 中文名
name_en: Original Name
aliases: []
summary: 简要定义
node_type: genre
emergence: late-1970s
codified: early-1980s
places: []
derived_from: []
fusion_sources: []
influenced_by: []
related_scenes: []
body: Markdown 正文
~~~

后继流派由 `derived_from` 等正向关系反向计算，避免同时维护两份关系。场景、影响与直接衍生分开保存，不能用一个 `parents` 字段混合表达。

### Era

~~~yaml
label: 1970s
title: 年代标题
order: 1970
summary: 年代概述
events:
  - id: stable-event-id
    date: 1970
    title: 节点标题
    summary: 节点摘要
    genres: []
    albums: []
~~~

### Album reference

~~~yaml
title: Album Title
artist: Artist Name
year: 1970
cover: 可选
source: 可选
~~~

代表专辑是可复用的内部资料，不生成独立页面。具体字段与数据来源在真实内容样本阶段验证后确定。

## 5. 关系规则

- 所有实体使用稳定、可读的 ID；
- 引用只保存 ID，不复制名称；
- 构建时检查不存在的引用；
- 流派关系必须允许多个直接来源、融合来源和影响来源；
- 构建时检测直接衍生关系的循环；
- 删除内容前必须先检查反向引用。

## 6. 内容集合实现

使用 Astro Content Collections 的 glob loader 管理本地 Markdown 或数据文件。

- defineCollection 从 astro:content 导入；
- z 从 astro/zod 导入；
- glob 从 astro/loaders 导入；
- 集合之间优先使用 reference 或集中式解析函数；
- schema 只描述稳定字段，尚未验证的数据不提前固化。

内容编辑阶段先制作少量真实样本，验证数据来源、封面可用性与字段完整度，再决定是否需要自动导入工具。

## 7. 客户端代码边界

客户端代码只用于：

- 首页实时视觉与可选声音；
- 探索页的阅读进度、年代定位和节点详情；
- 局部关系网络的布局、筛选与聚焦。

不把整站改造成单页应用，不要求内容正文在浏览器中二次获取。

首页重型场景应延迟加载非首屏资源；探索网络进入可视区域后再加载。无需为历史与分类建立客户端路由切换，选中状态只通过原生 History API 或锚点同步。

## 8. 质量要求

每个阶段至少验证：

- Astro 类型检查无错误；
- 静态构建成功；
- 所有内部引用有效；
- 桌面与移动布局；
- 键盘浏览；
- 减少动态效果模式；
- 首页三种视觉能力模式；
- 探索网络失败时的按年代文字降级；
- 节点深链接、前进后退与关闭后的焦点恢复；
- 页面标题、描述、规范链接和分享信息。

## 9. 发布

构建产物为静态文件，部署到支持自定义域名的平台并绑定 fuckthe.rocks。平台选择在发布阶段根据构建、缓存和域名配置实测确定。
