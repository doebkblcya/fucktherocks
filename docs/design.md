# FuckTheRocks — 第一版体验设计

## 1. 设计方向

第一版采用白底黑字、冷峻克制的现代杂志风，并借用古典雕塑摄影的空间品质：大量留白、明确比例、强弱分明的侧光、石膏般的中性色和被当作藏品陈列的对象。

“古典雕塑感”描述的是构图、光线和空间，不要求页面直接堆放希腊雕像素材。摇滚感来自专辑封面、关系结构、文字态度和运动节奏，不依赖撕纸、火焰、霓虹、唱片机或效果器面板等惯用符号。

首页和探索页共享同一套编辑设计语言，但承担不同任务：

- 首页是高沉浸、低信息密度的三维品牌场景；
- 探索页是高信息密度、可持续阅读的二维知识界面；
- 错误页是最轻量的恢复界面。

现有旧版页面、布局、颜色和组件不作为设计参考。

## 2. 视觉基础

### 2.1 色彩

初始色彩方向如下，具体数值在原型阶段根据屏幕与封面实测微调：

~~~text
背景         #F2F1ED  微暖石膏白
主要文字     #111111  近黑
辅助文字     #77736C  暖灰
结构线       #CBC8C0  浅灰
浮层背景     #E8E6E0  浅石色
强调色       来自当前专辑封面或选中关系
~~~

页面不预设全站高饱和品牌色。首页当前专辑封面可以成为主要色彩来源；探索页关系类型主要依靠线型、粗细、箭头和标签区分，颜色只做辅助，不能成为唯一编码。

### 2.2 字体与排版

- 标题使用高对比、具编辑感的展示字体或经过验证的现代无衬线字体；
- 正文使用高可读性的中文字体系统；
- 英文流派名、专辑名、年份和编号使用更紧凑的排版；
- 字号、字重、字距和留白建立明显层级，不依赖卡片阴影区分内容；
- 中文正文保持正常阅读宽度，长段文字不覆盖在 WebGL 画布中；
- 最终字体在原型阶段根据中文覆盖、授权、加载体积和跨平台表现确定。

### 2.3 图形语言

- 细线、编号、年份刻度和索引符号负责建立档案感；
- 专辑封面保持原始比例，不裁切成圆形或异形；
- 阴影轻且柔和，物体像悬浮印刷品，不像厚重 UI 卡片；
- 动效强调惯性、聚焦与空间变化，避免持续抖动、频闪和无意义噪点；
- 非当前内容保持低对比或灰度，当前内容恢复清晰度和色彩。

## 3. 首页：3D 专辑画廊

### 3.1 页面任务

首页只负责建立品牌印象，并把用户送往探索页。它不是专辑目录，也不承担完整知识阅读。

~~~text
┌──────────────────────────────────────────┐
│ FUCK THE ROCKS                  EXPLORE  │
│                                          │
│       固定杂志文字层                      │
│                3D 专辑球面                │
│                                          │
│  1954 — NOW                              │
│  SCROLL TO TRACE THE NOISE               │
└──────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────┐
│           [ ENTER THE NETWORK ]           │
└──────────────────────────────────────────┘
~~~

首页保持一段连续体验，不拆成多个常规内容区块。

### 3.2 专辑球面

- 第一版使用 24—40 张代表专辑；
- 封面分布在球面或接近球面的螺旋路径上；
- 排列顺序必须表达时间：早期根源位于路径起点，随后依次进入各年代；
- 封面不是随机装饰，当前视野必须能对应一个年份或时间区间；
- 远处封面使用低饱和、低对比和适度透明度；
- 接近中心的封面提高对比，当前封面恢复原色并轻微放大；
- 当前专辑的年份、艺人、标题和相关流派使用 HTML 显示在画布之外；
- 点击或键盘选择当前专辑时，可直接进入对应的探索页状态。

球面只展示经过编辑选择的代表专辑，不追求覆盖所有节点。

### 3.3 滚动与相机

- 保留浏览器原生纵向滚动，不拦截滚轮制造虚假滚动；
- 页面滚动进度映射为球体旋转、当前年代和当前专辑；
- 主要运动来自场景组旋转，相机保持相对稳定；
- 相机只做轻微推进、拉远和构图偏移，避免高速环绕；
- 鼠标或指针只提供幅度很小的视差，不影响内容定位；
- 触控设备使用同一滚动叙事，不要求拖拽完整三维球体；
- 页面离开可视区域或标签页隐藏时暂停渲染。

### 3.4 文字与入口

WebGL 画布只负责视觉场景。以下内容必须使用真实 HTML：

- 品牌名称；
- 一句核心定位；
- 当前年份与当前专辑信息；
- 滚动提示；
- “进入探索”按钮；
- 无障碍说明与降级内容。

入口在加载期间、静态模式和页面结尾始终可用，不能等待动画完成后才出现。

## 4. 探索页：时间化摇滚关系网络

### 4.1 默认阅读

探索页把时间顺序和流派关系放在同一个空间里。默认状态优先保证像杂志长文一样顺畅阅读：

- 年代使用清晰的纵向主轴；
- 历史事件、流派和代表专辑锚定在相应时间位置；
- 默认只显示核心主干和当前年代附近的必要关系；
- 关系线可以跨越年代，但不能压过标题和正文；
- 当前年代、阅读进度和筛选状态始终可辨认；
- 搜索、年代定位、分支筛选和文字索引固定在可发现的位置。

桌面端结构：

~~~text
┌──────────┬──────────────────────────┬──────────────┐
│ 年代导航 │ 时间主轴 + 局部关系网络   │ 节点详情面板 │
│          │                          │              │
│ 1950s    │ Blues ─────┐             │ POST-PUNK    │
│ 1960s    │            ├→ Hard Rock  │ 形成时间     │
│ 1970s    │ Psychedelic┘       │     │ 来源与后继   │
│ 1980s    │              Heavy Metal │ 代表专辑     │
│          │                          │              │
│ 搜索筛选 │                          │              │
└──────────┴──────────────────────────┴──────────────┘
~~~

探索页第一版使用 HTML 与 SVG 构成主要界面，不复制首页的三维球面语言。

### 4.2 关系聚焦

选择流派后：

- 突出当前节点及其一跳直接关系；
- 无关节点降低对比，但不立即从页面消失；
- 直接来源、后继、融合、影响和场景承接均显示文字标签或图例；
- 用户可以继续选择相邻节点，沿关系移动；
- 关闭详情后恢复原年代、筛选和滚动位置。

关系的基础视觉编码：

| 关系 | 基础表现 |
| --- | --- |
| 直接衍生 | 连续实线和方向箭头 |
| 融合来源 | 两条来源线汇入同一节点，并显示“融合”标签 |
| 影响 | 较细虚线或脉冲线，不暗示直接父子关系 |
| 场景承接 | 共享区域、括注或背景范围，而非强方向箭头 |
| 复兴／重新流行 | 从较早节点返回后期节点的“回声”线与时间标记 |

颜色不能成为唯一的关系区分方式。

### 4.3 节点详情

关系摘要放在长正文之前，帮助用户先理解节点在网络中的位置。

推荐顺序：

1. 中文名、原文名和一句话定义；
2. 形成时间、地点与场景；
3. 直接来源、融合来源、影响、后继；
4. 相关历史事件；
5. 1—3 张代表专辑；
6. 正文与来源说明。

桌面端使用可关闭侧栏；移动端使用底部面板或行内展开。打开面板时管理焦点，关闭后返回触发节点。

### 4.4 搜索与筛选

- 搜索直接定位流派、历史事件或代表专辑；
- 搜索结果在同页聚焦，不跳转独立搜索页；
- 分支筛选用于减少观察范围，不宣称形成唯一分类树；
- 年代定位滚动到相应时间位置；
- 活跃筛选必须可见并能一键清除；
- 浏览器前进后退能够恢复节点和年代状态。

## 5. 移动端

移动端不缩小桌面的完整关系图，而是保留同一叙事的简化版本。

### 首页

- 减少同时加载和显示的专辑数量；
- 降低渲染分辨率、视差幅度和相机运动；
- 保留原生滚动、当前年份、专辑信息和探索入口；
- 设备能力不足时直接采用静态杂志式封面构图。

### 探索页

- 年代仍是纵向主轴；
- 一次只突出当前节点、来源、后继和少量融合关系；
- 详情使用底部面板或行内展开；
- 不要求横向拖拽或双指缩放才能阅读；
- 搜索、筛选和年代定位使用可关闭工具面板。

## 6. 基础错误页

错误页延续全站排版，但保持完全静态。

~~~text
404 / LOST IN THE NOISE

这里没有这条路线。

[ 返回首页 ]  [ 进入探索 ]
~~~

不在错误页加载 3D 场景，不使用复杂动画掩盖错误信息。

## 7. 动效与能力模式

页面启动时根据 WebGL 支持、设备表现、触控环境和减少动态效果设置选择模式。模式选择不依赖单一设备型号判断。

| 模式 | 首页 | 探索页 |
| --- | --- | --- |
| 完整 | Three.js 专辑球面、滚动旋转、轻微相机和指针视差 | 完整关系线过渡、局部聚焦和状态动画 |
| 简化 | 减少封面、限制分辨率与运动，关闭非必要视差 | 减少过渡和同时显示的关系 |
| 静态 | 编辑排版完成的静态封面视觉、完整文案和入口 | 按年代组织的完整 HTML、文字关系索引和详情 |

`prefers-reduced-motion: reduce` 默认进入静态或接近静态的体验。用户仍能访问全部信息和操作。

任何模式下都必须：

- 保持主要操作可点击；
- 不因纹理、脚本或图谱加载失败而出现空白；
- 不劫持滚动或阻断浏览器导航；
- 保持键盘焦点清晰可见；
- 避免频闪和突然的大幅位移；
- 不自动播放声音。

## 8. 响应式与可访问性

- 正文和控件满足 WCAG 2.2 AA 对比度；
- 所有功能支持键盘操作；
- 触控目标不小于 44 × 44 像素；
- Canvas 对辅助技术隐藏，关键信息保留在 HTML 中；
- 探索网络提供等价文字索引；
- 历史节点使用原生可展开语义或等价实现；
- 当前选中状态不只依赖颜色表达；
- 动态更新的专辑或节点信息避免形成高频读屏播报；
- 字体、封面或 JavaScript 未加载时仍保留可理解的页面结构。

## 9. 需要制作的关键设计状态

第一版只有三个路由，但至少需要验证以下界面状态：

1. 首页完整 WebGL 状态；
2. 首页简化和静态状态；
3. 探索页默认时间阅读状态；
4. 探索页选中流派与详情状态；
5. 探索页搜索和筛选状态；
6. 探索页文字降级状态；
7. 移动端首页；
8. 移动端探索及底部详情；
9. 基础错误页。

## 10. 设计约束

- 首页不堆叠常规内容卡片；
- 专辑球面必须表达时间，不做随机图片装饰；
- 探索页不默认显示所有节点和所有边；
- 不把每个区块都做成独立特效；
- 不让 3D 场景承载必须阅读的正文；
- 不为视觉效果牺牲导航、性能、对比度或设备兼容；
- 不将旧版页面的临时样式迁移到新设计系统。
