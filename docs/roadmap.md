# FuckTheRocks — 路线图

> 从 `product.md` 的 MVP 范围与 `tech-design.md` 的方案派生。按里程碑推进，MVP 优先。

## 1. 里程碑总览

| 里程碑 | 目标 | 交付物 |
| --- | --- | --- |
| M0 项目初始化 | 搭起可运行骨架 | Astro 脚手架、目录结构、Content Collections schema、Tailwind、基础布局 |
| M1 内容骨架 | 建立分类学与时间线框架 | 首批核心流派（含父子/融合关系）、发展史年代框架 |
| M2 词条模板 | 跑通页面渲染 | 流派页、乐队页、专辑页、发展史页模板 |
| M3 导入管线 | 自动化结构化数据 | MusicBrainz 导入脚本 + 首批乐队/专辑数据 |
| M4 检索与首页 | 完成浏览闭环 | Pagefind 搜索、首页整合、导航 |
| M5 MVP 上线 | 发布首版 | CI 部署、自定义域名 fuckthe.rocks、内容初充 |

## 2. 里程碑明细

### M0 项目初始化

- `npm create astro` 初始化项目，TypeScript + Tailwind；
- 建立 `src/content/{genres,artists,albums,eras}` 目录与 `content.config.ts`（zod schema）；
- 基础布局（header/导航/footer）、暗色主题；
- 配置 GitHub Actions（build + 部署占位）。

### M1 内容骨架

- 手写首批核心流派（约 15-20 个）：如 摇滚乐根源、蓝调摇滚、硬摇滚、重金属、朋克、后朋克、另类摇滚、前卫摇滚、碾核/极端金属等，明确父子与融合关系；
- 建立发展史年代骨架（1950s-2020s），每年代 1-2 个关键事件占位。

### M2 词条模板

- 流派页：定义、起源、父/子流派、融合来源、代表乐队/专辑、正文；
- 乐队页：成员、年代、流派标签、专辑列表、简介；
- 专辑页：曲目、厂牌、流派标签、点评；
- 发展史页：年代时间线 + 事件关联跳转。

### M3 导入管线

- 实现 `scripts/import-musicbrainz.ts`（节流、幂等、风格标签映射）；
- 导入首批里程碑乐队/专辑（如 Led Zeppelin、Black Sabbath、Nirvana 等）；
- 人工补写中文译名、叙事、里程碑判定。

### M4 检索与首页

- 接入 Pagefind（构建后索引 + 前端搜索框）；
- 首页整合：年代导航、流派速览、代表专辑；
- 全局导航与交叉引用联调。

### M5 MVP 上线

- 部署到托管平台，绑定 `fuckthe.rocks`；
- CI 自动化（push main → build → 部署 + Pagefind）；
- 内容初充检查 + 发布。

## 3. MVP 之后（Backlog，按优先级）

| 优先级 | 项 | 说明 |
| --- | --- | --- |
| 高 | 分类学图谱可视化 | `/taxonomy` 页流派有向图（D3/cytoscape） |
| 高 | 内容扩充 | 更多流派、乐队、专辑、发展史事件 |
| 中 | 图片体系 | 专辑封面/乐队照（Cover Art Archive 等，甄别版权） |
| 中 | 关系页 | 「流派反查」「乐队全部专辑」等聚合页 |
| 低 | 多语言 | 中英双语全量条目 |
| 低 | 曲目独立详情 | 曲目级页面与乐理/歌词信息 |

## 4. 依赖与风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| MusicBrainz 风格标签与自有分类学不一致 | 导入后标签错配 | 建立标签→流派 slug 映射表，人工复核 |
| 中文叙事内容生产慢 | MVP 内容单薄 | 先精做核心条目，正文允许逐步补全 |
| 专辑封面/图片版权 | 上线合规风险 | MVP 用占位图或 CC0 图源，商业图后补 |
| 内容量增长导致构建变慢 | 体验下降 | 关注 Pagefind 索引与图片处理，必要时迁移内容层 API |
