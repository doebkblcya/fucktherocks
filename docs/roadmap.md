# FuckTheRocks — 第一版实施路线

## 当前状态

项目已有可构建的 Astro 骨架、基础布局、设计变量和黑胶 SVG，但现有页面与内容模型仍基于旧范围。当前先整理并确认内容资料；资料达到可入站状态后，再按“首页 + 探索页”的新产品定义重构网站。

## 阶段 1：资料整理与内容确认

目标：先确定探索页实际要表达的时间阶段、核心流派和关系，避免用空数据设计图谱。

- 整理用户提供的原始资料并保留可追溯归档；
- 确认摇滚发展阶段和核心流派网络；
- 校正直接衍生、融合、影响和场景承接关系；
- 为关键阶段和流派选择少量代表专辑；
- 用真实样本确认文字长度、引用方式、专辑字段和封面来源。

完成标准：

- 发展与分类总纲由“待确认”变为“可入站”；
- 第一版核心节点及关系边界已经确定；
- 真实样本能够同时覆盖年代、事件、流派和代表专辑；
- 数据来源选择有实测依据。

## 阶段 2：收拢工程骨架

目标：让代码结构与已经确认的第一版范围一致。

- 调整导航与路由骨架；
- 建立首页与探索页，移除第一版独立发展、分类和流派详情路由；
- 将内容集合收拢为 Genre、Era 与 Album reference；
- 更新 Astro 6 内容集合写法；
- 建立引用检查与基础页面元信息。

完成标准：

- 首页与探索页均可构建；
- 导航只保留两个主要入口；
- 示例内容可以通过 schema 校验并互相引用。

## 阶段 3：首页体验原型

目标：先验证第一版风险最高的视觉体验。

- 完成“黑胶沟槽 → 时间路线 → 流派网络”的连续动效原型；
- 验证滚动、指针与触控交互；
- 建立完整、简化、静态三种能力模式；
- 加入用户主动开启的声音原型；
- 在桌面和移动设备上实测。

完成标准：

- 首页无需内容卡片也能表达网站主题；
- 单一探索入口始终清晰可用；
- 不支持高级效果的浏览器不会出现空白或阻断；
- 视觉方案确认后再固化具体渲染技术。

## 阶段 4：探索页时间骨架

目标：先跑通探索页在没有关系图增强时的完整阅读体验。

- 实现纵向年代主轴；
- 实现可展开历史节点；
- 展示相关流派和代表专辑；
- 支持定位当前年代与阅读进度；
- 实现流派文字索引和页面内节点详情；
- 用 URL 参数或锚点保存当前节点。

完成标准：

- 无 JavaScript 时仍可阅读完整时间线；
- 移动端不需要横向拖动；
- 展开、收起和锚点链接可通过键盘操作；
- 浏览器前进后退能够恢复节点状态；
- 内容引用在构建时通过检查。

## 阶段 5：关系网络与真实内容整合

目标：在同一个探索页中加入流派关系追踪，并接入已确认内容，不另建分类页面。

- 实现流派关系数据转换；
- 将流派节点锚定到时间轴对应位置；
- 实现局部可交互关系网络；
- 区分直接来源、融合、影响和场景承接；
- 选择节点时高亮直接关系并打开同页详情；
- 保留用户当前年代、筛选和视口状态。
- 接入历史节点、流派正文和代表专辑；
- 验证同一流派和专辑在多个节点中的复用。

完成标准：

- 用户能从任一主要流派查看直接关系；
- 时间位置、关系网络和节点详情引用一致；
- 图谱不可用时仍可通过文字索引浏览；
- 移动端可完成节点选择、关系阅读和详情关闭；
- 用户不需要在“发展”和“分类”两个栏目之间切换。

## 阶段 6：整合发布

目标：完成第一版公开访问。

- 完成响应式、可访问性与性能检查；
- 完成首页动效和探索页之间的视觉衔接；
- 补齐页面标题、描述与分享信息；
- 确定静态托管平台；
- 绑定 fuckthe.rocks；
- 建立自动构建与发布。

完成标准：

- 类型检查和生产构建通过；
- 核心浏览路径无断链；
- 低性能设备与减少动态效果模式可用；
- 域名可访问且发布过程可重复。

## 执行原则

- 每阶段先用最小真实样本验证，再扩充；
- 首页效果、图谱布局和数据来源均以实测结果为决策依据；
- 不为未进入当前阶段的问题提前增加架构；
- 每完成一个阶段，同步更新文档中的当前状态。
