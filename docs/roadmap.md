# FuckTheRocks — 第一版实施路线

## 当前状态

产品范围、视觉方向和技术边界已经重新确认：

- 第一版只有 3D 专辑画廊首页、时间化摇滚关系网络和基础错误页；
- 首页采用白底黑字的冷峻现代杂志风，以 Three.js 专辑球面作为核心视觉；
- 探索页采用纵向时间轴、HTML 内容与 SVG 局部关系网络；
- 旧版网站页面、布局、样式和内容配置不再使用，工程从干净骨架重新建立；
- 原始资料、探索图母稿、来源底账和资料处理脚本继续保留。

不等待全部 175 篇资料完成后才开始设计。首页和探索页分别用最小真实样本验证，内容与实现随后迭代扩展。

## 阶段 0：范围与文档重置

目标：建立唯一、无冲突的第一版定义。

- 将页面范围收敛为首页、探索页和 404；
- 确认首页 3D 专辑球面方向；
- 确认白底黑字、冷峻杂志和雕塑摄影式空间感；
- 确认探索页不拆分历史与分类；
- 明确完整、简化和静态三种能力模式；
- 清除旧版网站实现，保留资料与工程配置。

完成标准：

- `product.md`、`design.md`、`implementation.md` 和 `roadmap.md` 相互一致；
- 旧页面不再被当作设计或代码基础；
- 后续工作只围绕三个路由展开。

状态：已完成。

## 阶段 1：干净工程骨架

目标：从空白实现建立三个可构建页面和新的设计基础。

- 建立 `/`、`/explore` 和 `/404`；
- 建立新的全站布局、字体层级、色彩变量和基础焦点样式；
- 导航只保留品牌和探索入口；
- 建立静态首页占位、探索页内容骨架和完整 404；
- 建立新的 Genre、Era 和 Album 内容集合样本；
- 加入引用检查和基础页面元信息。

完成标准：

- 三个页面均可静态构建；
- 不存在旧版栏目链接和样式残留；
- 无 JavaScript 时可以访问首页入口、探索骨架和 404；
- 示例内容通过 Schema 与引用检查。

## 阶段 2：首页 3D 原型

目标：优先验证第一版风险最高的三维视觉和滚动手感。

- 选择 24—40 张跨年代代表专辑作为原型数据；
- 验证封面来源、展示方式、替代文本和图片规格；
- 使用 Three.js 建立球面螺旋和共享几何体；
- 使用原生滚动进度驱动场景旋转；
- 使用 GSAP 或阻尼插值控制平滑过渡；
- 保持相机稳定，只做轻微推进和构图偏移；
- 建立当前年份与专辑的 HTML 信息层；
- 完成首页结尾的单一探索入口。

同时实现：

- 完整模式；
- 简化模式；
- 静态模式；
- WebGL 初始化失败和 context lost 降级；
- 移动端封面数量、分辨率与运动缩减。

完成标准：

- 球面能够读出时间顺序，不是随机图片球；
- 原生滚动未被劫持；
- 页面加载期间和静态模式下入口始终可用；
- 桌面滚动稳定，移动设备不存在不可接受的卡顿、发热或内存增长；
- `prefers-reduced-motion` 不出现持续三维运动。

## 阶段 3：探索页真实内容切片

目标：用一段足够复杂的真实历史验证内容模型和关系语言。

首个样本选择 1975—1994 年，覆盖：

- Punk → Post-Punk / Hardcore；
- Post-Punk → Gothic / Industrial / Alternative；
- Hardcore → Post-Hardcore / Emo / Crossover；
- NWOBHM → Thrash → Death / Black Metal；
- Alternative 地下网络 → Grunge 主流突破。

样本规模建议：

- 约 15 个核心流派节点；
- 约 5 个历史事件；
- 约 12 张代表专辑；
- 覆盖直接衍生、融合、影响和场景承接四种关系。

工作内容：

- 从内容母稿提取样本；
- 核对稳定 ID、时间、地点、关系和来源；
- 用真实正文验证详情长度；
- 验证 Album 数据同时服务首页与探索页；
- 明确存在争议的边界和不进入默认图谱的弱关系。

完成标准：

- 样本可以回答每个节点何时形成、从哪里来、通向哪里；
- 四种关系均有真实案例；
- 内容字段能够支撑首页、时间线、图谱和详情；
- 样本状态达到“可入站”。

## 阶段 4：探索页静态时间骨架

目标：先完成没有关系图增强也能使用的内容页面。

- 实现纵向年代主轴；
- 实现历史节点和流派的服务端 HTML；
- 展示相关流派和代表专辑；
- 实现年代定位、阅读进度和文字索引；
- 实现页面内节点详情；
- 用查询参数或锚点保存当前年代和节点；
- 完成桌面侧栏与移动端底部详情。

完成标准：

- 无 JavaScript 时仍可阅读全部样本；
- 移动端不需要横向拖动或缩放；
- 展开、收起和锚点可通过键盘操作；
- 浏览器前进后退能够恢复节点状态；
- 关闭详情后恢复滚动位置与键盘焦点。

## 阶段 5：局部关系网络

目标：在静态时间骨架上增加关系追踪，不创建独立分类页面。

- 根据时间和编辑分支泳道生成稳定节点位置；
- 使用 SVG 绘制关系线、箭头、范围和图例；
- 区分直接衍生、融合、影响和场景承接；
- 默认只显示核心和当前年代附近的关系；
- 选择节点时突出一跳关系并打开详情；
- 实现搜索、分支筛选和年代定位联动；
- 保留当前年代、筛选、视口和 URL 状态；
- 建立关系图加载失败时的文字降级。

完成标准：

- 用户能从任一核心流派查看直接关系；
- 相同内容每次打开的位置稳定；
- 时间位置、关系线和详情引用一致；
- 颜色不是关系类型的唯一编码；
- 移动端可以完成节点选择、关系阅读和详情关闭。

## 阶段 6：扩充完整第一版内容

目标：从验证切片扩展到内容母稿中的 11 个阶段。

- 确认第一版核心节点边界；
- 分阶段接入根源、早期摇滚、60—70 年代扩张和 21 世纪网络；
- 为关键阶段和流派选择少量代表专辑；
- 核对直接衍生、融合、影响和场景关系；
- 对来源不足和存在争议的关系降级或暂缓显示；
- 调整首页代表专辑，使其覆盖完整年代但不成为“最佳专辑榜单”。

完成标准：

- 探索页可从根源连续阅读到当代；
- 默认图谱保持可读，不因内容增加变成全部展开的毛线团；
- 每个核心节点至少具有简要定义、时间、关系、代表专辑和来源；
- 首页与探索页引用同一份已确认 Album 数据。

## 阶段 7：整合与发布

目标：完成第一版公开访问。

- 完成响应式、可访问性和性能检查；
- 完成首页到探索页的视觉衔接；
- 完成所有模式和失败状态测试；
- 补齐页面标题、描述、规范链接和分享信息；
- 检查封面来源、替代文本和必要权利说明；
- 确定静态托管平台；
- 配置自定义 404；
- 绑定 `fuckthe.rocks`；
- 建立可重复的构建与发布流程。

完成标准：

- 类型检查和生产构建通过；
- 核心浏览路径无断链；
- 低性能设备、无 WebGL、无 JavaScript 和减少动态效果模式可用；
- 首页不阻塞探索入口；
- 404 能把用户带回首页或探索页；
- 域名可访问且发布过程可重复。

## 执行原则

- 每个高风险体验先用最小真实样本验证；
- 首页 3D 场景和探索关系网络分别控制复杂度；
- 内容没有确认来源时，不用视觉效果掩盖不确定性；
- 不为未进入当前阶段的问题提前增加架构；
- 不恢复旧版栏目或组件；
- 每完成一个阶段，同步更新文档中的当前状态。
