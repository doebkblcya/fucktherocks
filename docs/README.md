# FuckTheRocks：现行规范

这是网站产品与体验的唯一现行说明。它只记录稳定决策，不抄录条目数量、专辑清单或已完成阶段；这些会变化的事实以 `src/data/` 和构建结果为准。原始资料和证据另见 [`materials/`](./materials/README.md)。

## 核心任务

网站要讲清两件事：摇滚流派如何随时间出现、并行和分化；每个分类主要是什么、听起来怎样、与相邻分类有何区别。关系必须区分衍生、融合、影响等类型，不能把复杂历史画成唯一父系。

视觉风格是白底黑字、冷峻的极简现代杂志风。首页可以沉浸，知识界面首先要清楚；少用说明口号、装饰标签和无关动效。

## 页面范围

| 地址 | 职责 |
| --- | --- |
| `/` | 3D 专辑画廊；按时间顺序建立视觉入口，通往探索页 |
| `/explore` | 时间线、流派分类和可追踪的直接关系 |
| `404` | 说明地址无效，返回首页或探索页 |

不设独立的阅读路线、场景／媒介、乐队百科、专辑目录或流派详情页面。唱片、城市、媒介等史实只在解释时期或流派时出现。若以后需要新页面，先明确它解决哪项核心任务，再调整本规范。

## 首页

- 观众位于专辑球面内部，封面按时间而非随机顺序排列；不把它做成外部观看的装饰球。
- 使用浏览器原生纵向滚动控制视角，镜头环视要平缓，不劫持滚轮；指针仅提供轻微视差。
- 当前专辑只显示年份、名称、艺人、流派线索和一句介绍，不叠加杂志封面式说明或卡片墙。
- 封面保持可辨认的原始比例；主要文字和探索入口是画布外的 HTML，加载期间也可使用。
- 完整模式有 3D 环视；简化模式降低分辨率与运动量；静态模式保留封面、品牌和入口。减少动态效果、WebGL 失败或上下文丢失时仍能访问网站。

## 探索页

- 时间线从根源延伸到当代，以时期为行、宽泛脉络为列，展示条目大致形成的位置；位置不是精确诞生年或终止年。桌面可横向比较并行发展，手机改为同顺序的单列分组。
- 分类索引先给出大类和具体分组，再列出所有条目的名称、类型、形成区间和一句定义。分组便于检索，不是互斥的自然分类树。
- 点击时间线名称可定位分类条目；有深读内容的条目再展开声音特征、代表人物或录音、分类边界和直接关系。没有额外内容的条目不显示空展开。
- 关系显示类型和简短解释，弱证据假设不直接入站。搜索只用于定位名称、时期或声音特征；查询参数可分享选中的条目。
- 不默认铺满连线，也不以未经证实的面积、数量或路径暗示流派的重要性。可视化应先让时间位置和分类结构容易理解。

## 内容与实现边界

- `src/data/explore-eras.json`、`explore-genres.json`、`explore-structure.ts`、`explore-relations.json`、`explore-relation-notes.json` 和 `explore-reading.ts` 是页面实际读取的数据。改动时须核对分组、时间位置和引用的一致性。
- `src/data/home-albums.json` 是首页选辑与文案；`public/covers/manifest.json` 记录图片文件和来源。不要在文档里再维护第二份完整专辑表。
- `docs/materials/` 是编辑资料，不等于已核实的上线事实。新的叙述先核对年代、名称、类型与关系依据，再归纳入 `src/data/`；不把文章主题映射误当作逐句证据。
- Astro 静态输出正文；Three.js 只用于首页。探索页使用原生 HTML，脚本只增强搜索、跳转与可分享状态。无 JavaScript 时仍能阅读时间线、分类和原生详情。
- 手机端不要求缩放巨型图谱；键盘焦点、触控目标、对比度和减少动态效果都必须可用。任何模式都不应出现空白首屏或阻断导航。

## 下一步核对

优先逐条核对形成区间、分类边界与关系来源，补强资料薄弱的条目和 2000 年后的非欧美发展，再决定是否需要更复杂的聚焦关系可视化。不要为了显得内容丰富而新增旁支页面。
